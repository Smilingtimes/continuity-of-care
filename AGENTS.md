# Workspace Instructions (continuity-of-care)

This is the owner's platform-neutral practice library, not an application.

1. Read `ME.md` (the lean core), then `NOW.md` for current priorities.
2. Read `START-HERE.md` when beginning project work.
3. Read `personal/` files only when the task involves the owner personally — career planning, writing in their voice, life reflection, or values-sensitive decisions. The depth map in `ME.md` says which file answers what.
4. For named work, read the project's `PROJECT.md`, `SKILLS.md` when present, and nearest `AGENTS.md`.
5. Use `SKILL-REGISTRY.md` for the first shortlist and the owner's detailed skill catalog (if they keep one) for deeper discovery.
6. **Catalog setup check:** if `SKILL-REGISTRY.md` has no master catalog linked, the workspace is not fully set up. Before deep skill discovery, ask the owner to choose: (a) create their own skill catalog — a table of skills with status, platform, and selection notes, in Notion, a spreadsheet, or a Markdown file here; or (b) reference the public example catalog linked in `SKILL-REGISTRY.md`. Record their choice and the date in `SKILL-REGISTRY.md`.
7. Read full skill instructions only after selecting a relevant skill and confirming it is available in the current platform.
8. Reassess skill needs at planning, building, debugging, release, and maintenance junctures.
9. Preserve the owner's writing and files. Never overwrite or delete without permission.

Teach in plain language. Separate verified facts, inferences, recommendations, and unknowns. Explain why a practice fits. Prefer small, reviewable stages. Never claim success without checking. Treat accessibility, privacy, safety, and effects on people as requirements.

Never store secrets or unnecessary sensitive data here. Date expiring information, update the existing source of truth, and record consequential decisions. Keep platform-specific instructions concise and point to shared context.
